from collections import Counter


class MyDecisionTree:
    def __init__(self, max_depth=3, min_samples_split=2):
        self.max_depth = max_depth
        self.min_samples_split = min_samples_split
        self.tree = None

    def fit(self, X, y):
        self.tree = self._build_tree(X, y, depth=0)
        return self

    def predict(self, X):
        return [self._predict_one(row, self.tree) for row in X]

    def _build_tree(self, X, y, depth):
        if self._should_stop(y, depth):
            return self._make_leaf(y)

        split = self._find_best_split(X, y)
        if split is None:
            return self._make_leaf(y)

        left_X, left_y, right_X, right_y = self._split_data(
            X, y, split["feature_index"], split["threshold"]
        )

        return {
            "type": "node",
            "feature_index": split["feature_index"],
            "threshold": split["threshold"],
            "left": self._build_tree(left_X, left_y, depth + 1),
            "right": self._build_tree(right_X, right_y, depth + 1),
        }

    def _should_stop(self, y, depth):
        return (
            len(set(y)) == 1
            or depth >= self.max_depth
            or len(y) < self.min_samples_split
        )

    def _make_leaf(self, y):
        prediction = Counter(y).most_common(1)[0][0]
        return {"type": "leaf", "prediction": prediction}

    def _find_best_split(self, X, y):
        best_split = None
        best_gini = 1.0
        feature_count = len(X[0])

        for feature_index in range(feature_count):
            values = sorted(set(row[feature_index] for row in X))
            thresholds = self._candidate_thresholds(values)

            for threshold in thresholds:
                left_X, left_y, right_X, right_y = self._split_data(
                    X, y, feature_index, threshold
                )
                if not left_y or not right_y:
                    continue

                gini = self._weighted_gini(left_y, right_y)
                if gini < best_gini:
                    best_gini = gini
                    best_split = {
                        "feature_index": feature_index,
                        "threshold": threshold,
                        "gini": gini,
                    }

        return best_split

    def _candidate_thresholds(self, values):
        return [
            (values[index] + values[index + 1]) / 2
            for index in range(len(values) - 1)
        ]

    def _split_data(self, X, y, feature_index, threshold):
        left_X = []
        left_y = []
        right_X = []
        right_y = []

        for row, label in zip(X, y):
            if row[feature_index] <= threshold:
                left_X.append(row)
                left_y.append(label)
            else:
                right_X.append(row)
                right_y.append(label)

        return left_X, left_y, right_X, right_y

    def _weighted_gini(self, left_y, right_y):
        total = len(left_y) + len(right_y)
        return (
            len(left_y) / total * self._gini(left_y)
            + len(right_y) / total * self._gini(right_y)
        )

    def _gini(self, y):
        counts = Counter(y)
        total = len(y)
        return 1 - sum((count / total) ** 2 for count in counts.values())

    def _predict_one(self, row, node):
        if node["type"] == "leaf":
            return node["prediction"]

        if row[node["feature_index"]] <= node["threshold"]:
            return self._predict_one(row, node["left"])

        return self._predict_one(row, node["right"])


```python
def main():
```

## Assistant

はい。今やっている「分割ポイントを探す」は、Decision Tree の中心です。

ざっくり言うと、分割の特定には2段階あります。

```text
1. 候補を作る
2. どの候補が一番よいか評価する
```

たとえば今回なら候補はこうです。

```text
Age <= 19.0
Age <= 21.0
Age <= 23.5

Money <= 2000.0
Money <= 4500.0
Money <= 7000.0
```

この候補の中から、「分けた後にラベルが一番きれいに分かれるもの」を選びます。

---

代表的な評価方法は主にこのあたりです。

**Gini不純度**

CART という有名な決定木アルゴリズムでよく使われます。

考え方は、

```text
そのグループの中で、ラベルがどれくらい混ざっているか
```

です。

たとえば、

```text
[No, No, No]
```

は完全にそろっているので不純度は低いです。

```text
[No, Yes, No, Yes]
```

は混ざっているので不純度が高いです。

Gini は分類問題でかなりよく使われます。今回の実装で最初に使うなら、Gini が一番おすすめです。式も比較的シンプルです。

```text
Gini = 1 - 各クラスの割合^2 の合計
```

たとえば `[No, No, Yes, Yes]` なら、

```text
No:  2/4 = 0.5
Yes: 2/4 = 0.5

Gini = 1 - (0.5^2 + 0.5^2)
     = 1 - 0.5
     = 0.5
```

`[No, No]` なら、

```text
No: 2/2 = 1.0

Gini = 1 - 1.0^2
     = 0
```

完全にそろっているので `0` です。

---

**Entropy / Information Gain**

ID3 や C4.5 系の決定木でよく出てきます。

これも目的は Gini と似ていて、

```text
ラベルの混ざり具合を測る
```

ことです。

ただし式に `log` が出てきます。

```text
Entropy = - Σ p * log2(p)
```

Entropy が高いほど混ざっていて、低いほどそろっています。

分割前の Entropy と、分割後の Entropy を比べて、

```text
どれくらい情報が増えたか
```

を見るのが Information Gain です。

```text
Information Gain = 分割前の不純度 - 分割後の不純度
```

Gini は「分割後の不純度が小さいもの」を選ぶ。
Information Gain は「不純度が大きく減るもの」を選ぶ。

言い方は違いますが、かなり近いことをしています。

---

**Gain Ratio**

Information Gain の改良版です。

Information Gain だけだと、値の種類が多い特徴量を過剰に好むことがあります。

たとえば `UserID` みたいな特徴量があると、各ユーザーごとに分けられてしまい、訓練データにはぴったり合うけど汎化しない木になりやすいです。

Gain Ratio はそこを補正します。

C4.5 で使われます。

---

**Misclassification Error**

これはもっと単純です。

```text
一番多いクラス以外の割合
```

を見ます。

たとえば、

```text
[No, No, Yes]
```

なら一番多いのは `No` で 2件。

```text
間違い率 = 1 - 2/3 = 1/3
```

ただ、分割を選ぶ基準としては Gini や Entropy より鈍いので、学習時にはあまり主役にはなりません。木を剪定するときなどに出てくることがあります。

---

今回おすすめなのは **Gini不純度** です。

理由はこの3つです。

```text
1. 分類木の基本としてよく使われる
2. Entropy より式が簡単
3. scikit-learn の DecisionTreeClassifier でもデフォルトの1つ
```

なので、今の学習プロジェクトではまず Gini で十分です。

---

今回のデータで見ると、たとえば `Age <= 21.0` はこう分けます。

```text
左: [No, No]
右: [Yes, Yes]
```

左の Gini は `0`。
右の Gini も `0`。

なので分割後の Gini は `0` です。

これは最高です。

一方で `Age <= 19.0` だと、

```text
左: [No]
右: [No, Yes, Yes]
```

左は Gini `0` ですが、右は混ざっています。

だから `Age <= 21.0` の方が良い、となります。

---

この段階で理解しておくとよいことは、Decision Tree は「正しいルールを人間が教えている」のではなく、

```text
候補の分割を全部試す
分割後のラベルの混ざり具合を計算する
一番きれいに分かれた条件を採用する
```

という、かなり機械的な探索をしているということです。

次に進むなら、`gini(y)` を書いて、そのあと `weighted_gini(left_y, right_y)` を書くのが自然です。

## User

CART や ID3 や C4.5 はなに？

## Assistant

`CART`、`ID3`、`C4.5` は、どれも **Decision Tree を作るための代表的なアルゴリズム** です。

同じ「決定木」でも、木の作り方に流派があります。

**ID3**
ID3 は初期の有名な決定木アルゴリズムです。

特徴は、

```text
分類問題向け
分割基準に Entropy / Information Gain を使う
基本的にはカテゴリ特徴量を想定
```

たとえば、

```text
天気 = 晴れ / 曇り / 雨
```

みたいな特徴量を使って、

```text
どの特徴量で分けると一番情報量が増えるか
```

を見ます。

ID3 は基本形としてはわかりやすいですが、連続値や欠損値の扱いなどは弱めです。

---

**C4.5**
C4.5 は ID3 を改良したものです。

特徴は、

```text
分類問題向け
Information Gain ではなく Gain Ratio を使う
連続値を扱える
欠損値もある程度扱える
枝刈り pruning がある
```

ID3 より実用寄りです。

`Gain Ratio` を使う理由は、Information Gain だけだと「値の種類が多い特徴量」を好みすぎることがあるからです。

たとえば、

```text
user_id
```

みたいな特徴量があると、訓練データだけにはすごく合う分割ができてしまいます。でも新しいデータには弱いです。

C4.5 はその偏りを抑えようとします。

---

**CART**
CART は Classification And Regression Trees の略です。

特徴は、

```text
分類にも回帰にも使える
分類では Gini 不純度をよく使う
回帰では MSE などを使う
必ず二分木を作る
```

「必ず二分木」というのが大きいです。

たとえば特徴量がカテゴリで、

```text
Color = Red / Blue / Green
```

だったとしても、CART は基本的に

```text
Color in {Red, Blue} ?
```

のような Yes/No 分岐にします。

一方、ID3 や C4.5 はカテゴリ値ごとに多分岐する形を取りやすいです。

```text
Color?
├── Red
├── Blue
└── Green
```

---

今あなたが作っているものは、かなり **CART 寄り** です。

理由はこれです。

```text
Age <= 21.0 ?
├── Yes
└── No
```

という二分木を作ろうとしているからです。

さらに、次に Gini 不純度で分割を評価するなら、より CART らしくなります。

なので今の実装方針は、

```text
CART 風の分類木を、自分で小さく実装している
```

と考えるとよいです。

| アルゴリズム | 主な用途 | 分割基準 | 木の形 |
|---|---|---|---|
| ID3 | 分類 | Information Gain | 多分岐しやすい |
| C4.5 | 分類 | Gain Ratio | 多分岐しやすい |
| CART | 分類・回帰 | Gini / MSE | 二分木 |

最初に学ぶなら、今のように **CART + Gini + 二分木** で進めるのが一番実装しやすいです。

## User

もう少し、中身の仕組みを教えて、なぜこのような特徴になるのかを解説してください。

## Assistant

Decision Tree のアルゴリズム差は、主にこの3つから生まれます。

```text
1. どんな分割候補を許すか
2. 分割の良さを何で測るか
3. 木が複雑になりすぎたときにどう抑えるか
```

この違いが、ID3 / C4.5 / CART の特徴になります。

**ID3 の中身**
ID3 はかなり素朴です。

考え方は、

```text
今あるデータを一番よく分類できる特徴量を1つ選ぶ
その特徴量の値ごとに枝を作る
各枝で同じことを繰り返す
```

です。

たとえば特徴量が `Weather` で、

```text
Sunny
Cloudy
Rainy
```

の3種類あるなら、ID3 はこう分けやすいです。

```text
Weather?
├── Sunny
├── Cloudy
└── Rainy
```

なぜ多分岐になりやすいかというと、ID3 はもともと **カテゴリ特徴量** を前提にしていて、「ある特徴量を選んだら、その値ごとに枝を作る」という発想だからです。

分割の評価には `Information Gain` を使います。

```text
Information Gain = 分割前の Entropy - 分割後の Entropy
```

つまり、

```text
分割によってラベルの混ざり具合がどれだけ減ったか
```

を見ています。

ただし ID3 には弱点があります。

たとえば `UserID` のように、ほぼ全員違う値を持つ特徴量があるとします。

```text
UserID?
├── A001
├── A002
├── A003
├── A004
...
```

こう分けると、訓練データでは各枝に1人だけ入りやすいです。1人だけならラベルは必ずそろいます。

だから Entropy は下がります。

でもこれは本質的なルールではありません。新しいユーザーには役に立ちにくいです。

これが ID3 が「値の種類が多い特徴量を好みやすい」と言われる理由です。

---

**C4.5 の中身**
C4.5 は ID3 の問題をかなり現実向けに直したものです。

大きな改良は、

```text
Information Gain ではなく Gain Ratio を使う
連続値を扱える
欠損値を扱える
枝刈りをする
```

です。

一番重要なのは `Gain Ratio` です。

ID3 の Information Gain は、値の種類が多い特徴量を好みやすい。そこで C4.5 は、分割が細かすぎる場合にペナルティをかけます。

ざっくり言うと、

```text
Gain Ratio = Information Gain / 分割の細かさ
```

です。

正確には分母に `Split Information` という値を使います。

意味としては、

```text
その特徴量で分けると、データがどれくらい細かく散らばるか
```

です。

`UserID` のような特徴量は、データを細かく分けすぎます。すると分母が大きくなり、Gain Ratio は下がります。

だから C4.5 は ID3 よりも、

```text
訓練データにだけ都合よく合う特徴量
```

を選びにくくなります。

また、C4.5 は連続値も扱えます。

たとえば `Age` が、

```text
18, 20, 22, 25
```

なら、候補を作って、

```text
Age <= 19
Age <= 21
Age <= 23.5
```

のような分割を試します。

これは今あなたがやっている処理に近いです。

ただし C4.5 は、カテゴリ特徴量では多分岐もできます。

---

**CART の中身**
CART は発想がかなり統一されています。

最大の特徴は、

```text
必ず Yes/No の二分木にする
```

ことです。

たとえば `Age` なら、

```text
Age <= 21?
├── Yes
└── No
```

カテゴリ特徴量でも、

```text
Color in {Red, Blue}?
├── Yes
└── No
```

のように二分します。

なぜ CART は二分木なのかというと、CART は分類だけでなく回帰にも同じ枠組みを使いたいからです。

CART は名前の通り、

```text
Classification And Regression Trees
```

です。

分類なら、

```text
ラベルが混ざらないように分ける
```

回帰なら、

```text
数値のばらつきが小さくなるように分ける
```

というふうに、同じ「二分して、左右の不純度や誤差を下げる」処理で統一できます。

分類ではよく `Gini不純度` を使います。

```text
Gini = 1 - 各クラス割合の2乗の合計
```

たとえば、

```text
[No, No, Yes, Yes]
```

なら、

```text
No:  0.5
Yes: 0.5

Gini = 1 - (0.5^2 + 0.5^2)
     = 0.5
```

一方、

```text
[No, No]
```

なら、

```text
No: 1.0

Gini = 1 - 1.0^2
     = 0
```

完全にそろっているので `0` です。

CART はすべての候補分割について、

```text
左グループの Gini
右グループの Gini
それぞれのデータ数による重み付き平均
```

を計算します。

そして一番小さいものを選びます。

---

今のあなたの実装方針は、こういう処理です。

```text
1. Age の候補しきい値を作る
2. Money の候補しきい値を作る
3. 各候補でデータを左・右に分ける
4. 左右の Gini を計算する
5. 重み付き平均 Gini が一番低い分割を採用する
```

これは CART っぽいです。

なぜかというと、

```text
数値特徴量を threshold で二分する
Gini で評価する
Yes/No の木を作る
```

からです。

---

具体例で見ると、データはこれです。

```text
Age  Money  Buy
18   1000   No
20   3000   No
22   6000   Yes
25   8000   Yes
```

`Age <= 21` で分けると、

```text
左: No, No
右: Yes, Yes
```

Gini は、

```text
左: 0
右: 0
全体: 0
```

です。

一方、`Age <= 19` で分けると、

```text
左: No
右: No, Yes, Yes
```

右が混ざっています。

右側の Gini は、

```text
No:  1/3
Yes: 2/3

Gini = 1 - ((1/3)^2 + (2/3)^2)
     = 1 - (1/9 + 4/9)
     = 4/9
     = 0.444...
```

全体では左1件、右3件なので、

```text
weighted Gini = 1/4 * 0 + 3/4 * 0.444...
              = 0.333...
```

だから `Age <= 21` のほうが良いです。

---

まとめると、特徴の理由はこうです。

| アルゴリズム | なぜその特徴になるか |
|---|---|
| ID3 | カテゴリ特徴量を値ごとに分け、Information Gain を最大化する設計だから |
| C4.5 | ID3 の弱点を補うため、Gain Ratio・連続値対応・枝刈りを追加したから |
| CART | 分類と回帰を同じ枠組みで扱うため、二分木として分割評価を統一したから |

あなたが今作るなら、まずは CART の分類版だけで十分です。

つまり、

```text
数値特徴量
二分木
Gini不純度
再帰的に分割
```

これを作ると、Decision Tree の本質がかなり見えます。

今一番主流なのは、LightGBMだと思いますが、CARTというわけではないですか？

**Tool Call: LightGBM Features leaf-wise tree growth histogram official documentation, LightGBM Parameters gbdt dart rf official documentation**
Status: Completed

## Assistant

短く言うと、**LightGBM は CART そのものではないですが、内部で作っている1本1本の木はかなり CART 系です。**

ただし、あなたが今作っている単体の Decision Tree と LightGBM は、学習しているもののレイヤーが違います。

```text
CART:
1本の決定木を作るアルゴリズム

LightGBM:
小さい決定木を何本も足し合わせる Gradient Boosting の実装
```

LightGBM 公式ドキュメントでも、デフォルトの `boosting_type` は `gbdt`, つまり Gradient Boosting Decision Tree とされています。また LightGBM は leaf-wise に木を成長させる、と説明されています。  
Sources: LightGBM Parameters, Features  
https://lightgbm.readthedocs.io/en/stable/Parameters.html  
https://lightgbm.readthedocs.io/en/latest/Features.html

**CART と似ている部分**

CART は基本的にこうです。

```text
特徴量 <= しきい値 ?
├── 左
└── 右
```

LightGBM の木も、基本はこのような二分木です。

たとえば、

```text
age <= 21.5
```

のような split を作ります。なので「木の形」や「しきい値で二分する」という意味では CART 的です。

**CART と違う部分**

一番大きな違いは、分割の評価方法です。

あなたが今作っている CART 風の木では、分類なら Gini 不純度を使います。

```text
この分割をしたら、No / Yes がどれくらいきれいに分かれるか
```

を見る。

一方 LightGBM は Gradient Boosting なので、直接 `Yes/No` の混ざり具合だけを見ているわけではありません。

LightGBM は各データについて、

```text
今のモデルがどれくらい間違っているか
```

を見ます。そして、その間違いを次の木で補正します。

より具体的には、損失関数の

```text
gradient
hessian
```

を使って、

```text
この分割をすると損失がどれくらい減るか
```

を評価します。

つまり CART 風に言うと、

```text
Gini が下がる分割を探す
```

ではなく、

```text
目的関数の loss が下がる分割を探す
```

です。

**もう一つの違い: 木の伸ばし方**

普通の CART 実装では、木を depth-wise に伸ばすことが多いです。

```text
深さ1を全部作る
深さ2を全部作る
深さ3を全部作る
```

という感じです。

LightGBM は leaf-wise です。

```text
今ある葉の中で、一番 loss を減らせる葉だけを次に分割する
```

という伸ばし方をします。

だから同じ葉数なら精度が出やすいことがあります。ただし、データが少ないと過学習しやすいので、`num_leaves`, `max_depth`, `min_data_in_leaf` などで制御します。

**なので整理すると**

| 観点 | CART | LightGBM |
|---|---|---|
| 何を作るか | 1本の決定木 | 決定木の集合 |
| 木の形 | 二分木 | 二分木 |
| 分割基準 | Gini, MSE など | loss の改善量 |
| 学習対象 | ラベルそのもの | 今のモデルの誤差 |
| 木の伸ばし方 | 実装によるが depth-wise が多い | leaf-wise |
| 目的 | 単体で予測 | 多数の木を足して高精度化 |

だから、

```text
LightGBM は CART ではない
でも、CART 系の二分木を部品として使う Gradient Boosting
```

と捉えるのが一番正確です。

今あなたが実装している `Gini + 二分木` は、LightGBM に進む前の土台としてかなり良いです。次に理解する橋渡しは、「Gini で分割する」の代わりに「loss の減少量で分割する」と考えるところです。

## User

今のコードはGeniにはなっていないですが、よく混ざっているのを採用するようにしています。ここから学習を進めるにはどのようにするのですか？

## Assistant

たぶん今の状態は、分割候補ごとに左右へ分けて、

```text
左に No/Yes がどれくらい混ざるか
右に No/Yes がどれくらい混ざるか
```

を見られるところまで来ている、ということですね。

ここから学習を進めるには、次の順番がいいです。

**1. 「よく混ざっている」を採用しない**

Decision Tree では基本的に、採用したいのは **混ざっていない分割** です。

たとえばこれは良い分割です。

```text
左: No, No
右: Yes, Yes
```

これは悪い分割です。

```text
左: No, Yes
右: No, Yes
```

なので、もし今のコードが「よく混ざっているものを採用」しているなら、向きが逆です。

ただし、あなたの変数名やスコアの定義によっては、

```text
score が高い = よく分かれている
```

としている可能性もあります。

見るべきなのは名前ではなく意味です。

```text
混ざり具合を表す値なら、小さいものを選ぶ
きれいに分かれた度合いを表す値なら、大きいものを選ぶ
```

です。

---

**2. まず葉を作る**

一番良い分割が見つかったら、左右にデータを分けます。

```text
best_feature_index
best_threshold
```

が見つかったら、

```text
left_X, left_y
right_X, right_y
```

を作ります。

そして、まだ再帰しないなら、まずはこういう1段の木を作ります。

```python
self.tree = {
    "feature_index": best_feature_index,
    "threshold": best_threshold,
    "left_prediction": 左側で一番多いラベル,
    "right_prediction": 右側で一番多いラベル,
}
```

今回のデータなら、

```python
{
    "feature_index": 0,
    "threshold": 21.0,
    "left_prediction": "No",
    "right_prediction": "Yes",
}
```

のようになります。

これだけでも、もう `fit()` は「学習した」と言えます。

---

**3. predict を書く**

次は `predict()` です。

学習した条件を使って、新しいデータを分類します。

考え方はこうです。

```text
もし row[feature_index] <= threshold なら left_prediction
そうでなければ right_prediction
```

つまり、

```text
[19, 2000]
```

が来たら、

```text
Age <= 21.0
19 <= 21.0 なので No
```

です。

```text
[23, 7000]
```

なら、

```text
23 <= 21.0 ではないので Yes
```

です。

最初は1段の木だけで十分です。

---

**4. そのあと再帰に進む**

1段の木が動いたら、次にやるのが再帰です。

今は、

```text
root
├── left_prediction
└── right_prediction
```

ですが、再帰を入れると、

```text
root
├── left subtree
└── right subtree
```

になります。

つまり、左側のデータに対してもう一度「一番良い分割」を探します。右側も同じです。

```text
全体で一番良い分割を探す
左データで一番良い分割を探す
右データで一番良い分割を探す
さらにその先でも探す
```

これが Decision Tree の学習です。

---

ただし、無限に分割するとまずいので、停止条件が必要です。

代表的にはこの3つです。

```text
1. y が全部同じラベルになった
2. max_depth に到達した
3. データ数が少なすぎる
```

たとえば、

```text
左: No, No
```

なら、もう分ける必要はありません。葉にします。

```python
{"type": "leaf", "prediction": "No"}
```

一方、

```text
右: No, Yes, Yes, Yes
```

なら、まだ混ざっているので、さらに分割候補を探します。

---

今の段階でのおすすめ実装順はこれです。

```text
1. best split を探す
2. その split で左右に分ける
3. 左右それぞれの多数決ラベルを保存する
4. 1段だけの predict を作る
5. 動いたら、木構造を node / leaf に変える
6. 再帰で複数段にする
```

いきなり再帰に行かない方が理解しやすいです。

まずはこの形を目標にするといいです。


## Assistant

Decision Tree では、分割を止める条件がかなり重要です。止めないと、訓練データを覚え込みすぎます。

分割を止める代表的な条件はこのあたりです。

```text
1. y が全部同じラベルになった
2. max_depth に到達した
3. データ数が少なすぎる
4. 分割しても改善しない
5. 有効な分割候補がない
```

---

**1. y が全部同じラベルになった**

これは一番自然な停止条件です。

たとえば、あるノードに入った `y` がこうなら、

```text
["No", "No", "No"]
```

もう分ける必要がありません。

このノードに来たデータは `No` と予測すればいいです。

```python
{"type": "leaf", "prediction": "No"}
```

なので、

```python
if len(set(y)) == 1:
    stop
```

です。

---

**2. max_depth に到達した**

木が深くなりすぎるのを防ぐ条件です。

たとえば `max_depth = 3` なら、3段以上は分けません。

なぜ必要かというと、深くしすぎると訓練データに合わせすぎるからです。

たとえば最後には、

```text
1データ = 1葉
```

みたいな状態まで作れてしまいます。

これは訓練データには強いですが、新しいデータには弱くなりやすいです。これを過学習と呼びます。

```python
if depth >= self.max_depth:
    stop
```

止めたときは、そのノード内の多数決ラベルを予測にします。

---

**3. データ数が少なすぎる**

少ないデータから細かいルールを作ると、偶然に引っ張られやすいです。

たとえば2件しかないのにさらに分けると、

```text
1件ずつの葉
```

ができます。

これはあまり信頼できません。

なので、

```python
if len(y) < self.min_samples_split:
    stop
```

のようにします。

たとえば `min_samples_split = 2` なら2件未満では分けない。
`min_samples_split = 5` なら5件未満では分けない。

---

**4. 分割しても改善しない**

best split を探しても、Gini がほとんど下がらないなら分ける意味が薄いです。

たとえば分割前の Gini が `0.5` で、分割後の weighted Gini も `0.5` なら、ラベルの混ざり具合は改善していません。

```text
分割前 Gini - 分割後 Gini <= 0
```

なら止めてよいです。

少しだけ改善した場合も、ノイズかもしれません。

なので実用上は、

```python
if gain < self.min_impurity_decrease:
    stop
```

のような条件を使うことがあります。

ここで、

```text
gain = 分割前の Gini - 分割後の weighted Gini
```

です。

---

**5. 有効な分割候補がない**

すべての特徴量が同じ値だと、しきい値候補が作れません。

たとえば、

```text
X = [
  [20, 3000],
  [20, 3000],
  [20, 3000],
]
```

だと、どこで分けても意味がありません。

この場合、best split は見つかりません。

```python

    stop
```

です。

`leaf` の予測は、多数決です。

つまり、分割を止めるとは、

```text
これ以上ルールを細かく作らず、
このノードに入ったデータの多数派ラベルを予測にする
```

という意味です。

---

**1. Gini を MSE に変える**

分類では、

```python
score = self._weighted_gini(left_y, right_y)
```

でした。

回帰では、

```python
score = self._weighted_mse(left_y, right_y)
```

にします。

MSE は「そのグループ内の y が平均からどれくらいズレているか」です。

```python
def _mse(self, values):
    mean = sum(values) / len(values)
    return sum((value - mean) ** 2 for value in values) / len(values)
```

左右まとめた評価は、Gini と同じく件数で重み付けします。

```python
def _weighted_mse(self, left_y, right_y):
    total = len(left_y) + len(right_y)

    return (
        len(left_y) / total * self._mse(left_y)
        + len(right_y) / total * self._mse(right_y)
    )
```
